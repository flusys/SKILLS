# FLUSYS Template

The reference monorepo for building on `@flusys/*`: **Angular 22** dashboard + **NestJS 11**
backend, with every FLUSYS package already wired. A starting point, not a product.

This repo is meant to be driven by [Claude Code](https://claude.com/claude-code) through the
skills in [`.claude/skills/`](.claude/skills/) — see [CLAUDE.md](CLAUDE.md) for the contract and
[`.claude/README.md`](.claude/README.md) for how the tooling underneath those skills fits
together (agents, hooks, rules, workflows).

## Tech Stack

| Layer    | Stack                                                                    |
| -------- | ------------------------------------------------------------------------- |
| Frontend | Angular 22 (signals, standalone, zoneless) + `@flusys/ng-ui` + Tailwind v4 |
| Backend  | NestJS 11 + TypeORM + PostgreSQL + JWT                                    |
| API      | RPC over POST for entity CRUD; GET for domain reads (not REST)            |
| Ports    | Dashboard `http://localhost:3001` · Backend `http://localhost:3002`       |

## Quickstart

```bash
# 1. Clone as a fresh project (see CLAUDE.md "Using This Template" for the full stamping flow)
git clone <template-repo> my-app && cd my-app && rm -rf .git && git init

# 2. Install
cd backend && npm install && cd ../dashboard && npm install && cd ..

# 3. Configure
cp backend/.env.example backend/.env   # DB creds, JWT secrets, ADMIN_EMAIL/PASSWORD, etc.

# 4. Database
cd backend && npm run migration:run && npm run seed:all && cd ..

# 5. Run both apps
cd backend && npm run start:dev     # http://localhost:3002
cd dashboard && npm run start       # http://localhost:3001
```

Don't hand-run these steps against a fresh clone — `/bootstrap` does 2–4 for you (naming the app,
regenerating secrets, selecting `@flusys/*` packages, wiring config, migrating, seeding) from a
reviewed PRD. Run it manually only when you already know exactly what you're changing.

## The Workflow

```
requirements ──▶ /prd-generator ──▶ docs/prd-bootstrap.md
                                     docs/prd-feature-01-*.md …
                       │
  /bootstrap ──────────┤  first run: name the app, regenerate secrets, rewrite CLAUDE.md
                       │  every run: select packages, configure wiring, migrate, seed
                       │
  /develop-feature ────┘  one feature module per PRD, in dependency order
```

Each step is a Claude Code skill, invoked by name (`/prd-generator`, `/bootstrap`,
`/develop-feature`) or automatically when its description matches the task at hand. Review every
generated PRD before running `/bootstrap` — it's the contract the rest of the pipeline executes
without asking follow-up questions.

## Project Structure

```
backend/                  NestJS 11 API
  src/config/              modules.config.ts, entities.config.ts — every @flusys/* wiring point
  src/modules/              one folder per domain module (feature code lives here)
  src/persistence/          DataSource, migrations (generated, never hand-edited), seeds
  src/providers/             app-specific integrations (email, IAM sync, AI assistant)

dashboard/                Angular 22 app
  src/app/config/           provideXxxProviders() registration, mirrors backend/config
  src/app/pages/            route-level feature pages
  src/app/services/         app-specific services
  src/environments/         environment.ts — services.xxx base URLs per @flusys/* package

docs/                      PRDs (prd-bootstrap.md, prd-feature-*.md) and CLAUDE.RULES.md
                            — generated by prd-generator / rules-writer, not hand-written

.claude/                   Claude Code tooling — see .claude/README.md
  skills/                    workflow steps (prd-generator, bootstrap, develop-feature, refactor…)
  agents/                    isolated read-only subagents (code-reviewer)
  hooks/                     mechanical enforcement of Hard Rules (PreToolUse/PostToolUse)
  rules/                     path-scoped reminders surfaced when a matching file is opened/edited
  workflows/                 multi-agent JS scripts for fan-out work (refactor-sweep.js)
```

## Working with `@flusys/*` Packages

Packages are consumed from npm — you configure them, you never read or edit their internals
(enforced by [`.claude/hooks/block-protected-paths.sh`](.claude/hooks/block-protected-paths.sh)).
Every package exposes exactly three surfaces; see CLAUDE.md's [Working
Model](CLAUDE.md#working-model) table for backend/frontend registration, options, and
routes/entities file locations.
